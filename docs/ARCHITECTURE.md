# Архитектура операционной системы AeroOS

## 1. Концепция и цели
**AeroOS** — это легковесный дистрибутив Linux на базе пакетной базы Fedora, спроектированный с приоритетом на:
1. **Эргономику Windows 11**: Привычный рабочий стол, центрированная панель задач, Snap Layouts, файловый менеджер с вкладками, акриловый блюр и скругления.
2. **Экстремальную легкость**: Потребление ОЗУ < 600 МБ в простое, быстрый старт (< 12 сек на SSD), комфортная работа на 2–4 ГБ ОЗУ.
3. **Бесшовный запуск Windows-софта**: Интеллектуальный запуск `.exe` с аппаратной автоподстройкой (DXVK / WineD3D) + изолированный Bottles + WinApps (KVM/RAIL) для несовместимого тяжелого ПО.

## 3. Решение дилеммы: Почему Не Чистый Immutable?

В классических immutable-системах (Silverblue, Kinoite) обновление системы локально запускает процесс `rpm-ostree compose`.
На слабых машинах с 2 ГБ ОЗУ и 2-ядерными процессорами этот процесс:
1. Занимает до 100% CPU на 15–25 минут.
2. Часто падает из-за нехватки ОЗУ (OOM-killer).
3. Требует двойного дискового пространства под резервные deployment-деревья.

**Архитектурное решение AeroOS:**
Мы используем **минимальную классическую базу Fedora с Btrfs + Snapper**:
* При каждом `dnf update` Snapper автоматически создает pre- и post-снимки Btrfs.
* Время создания снимка: **< 0.1 секунды**.
* Затраты ОЗУ: **0 МБ**.
* В меню GRUB интегрируется `grub-btrfs`: при любом сбое пользователь выбирает предыдущее рабочее состояние в один клик.

## 4. Спецификация памяти для 2–4 ГБ ОЗУ

| Компонент | Стандартная Fedora Workstation | AeroOS Оптимизированная | Экономия |
| :--- | :--- | :--- | :--- |
| **Окружение (GNOME vs Plasma Minimal)** | ~900 МБ | ~450 МБ | **-450 МБ** |
| **Индексация диска (Tracker / Baloo)** | ~180 МБ + нагрузка на диск | 0 МБ (вырезаны) | **-180 МБ** |
| **Демон обновлений (PackageKit)** | ~150 МБ | 0 МБ (отключен) | **-150 МБ** |
| **Файрвол (Firewalld vs Nftables)** | ~65 МБ | ~5 МБ | **-60 МБ** |
| **Службы отчетов и модемов (ABRT, ModemManager)** | ~50 МБ | 0 МБ (отключены) | **-50 МБ** |
| **Эффективный объем подкачки (zRAM zstd)** | 100% RAM | 150% RAM с низким лагом | **+1.5-3 ГБ вирт. памяти** |
| **Итоговый холодный старт** | **~1.3–1.5 ГБ** | **~550–590 МБ** | **Экономия ~800+ МБ ОЗУ** |
